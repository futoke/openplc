# Краткая справка по Structured Text

ST (Structured Text) — текстовый язык программирования ПЛК из семейства IEC 61131-3. Здесь достаточно переменных, условий, таймера и памяти предыдущего состояния. Это не Python: блоки завершаются ключевыми словами, а инструкции — точкой с запятой.

## Цикл PLC и состояние

Задача вызывает `TankControl` каждые 20 мс (номинально 50 раз в секунду). Тело выполняется сверху вниз, затем управление возвращается Runtime. На следующем цикле тело выполняется заново. Не пишите бесконечный `WHILE`: он помешает завершению цикла.

Локальные переменные экземпляра программы сохраняют значения между вызовами. Начальное значение задаётся при инициализации, а не в начале каждого цикла. Сохранение между циклами не означает сохранения после перезапуска: в работе `RETAIN` не используется. После загрузки/перезапуска проверьте исходное состояние и при необходимости выполните RESET.

```iecst
IF NOT LowLevel THEN
    Pump := TRUE;
END_IF;
```

Если условие ложно, присваивания нет: `Pump` сохраняет старое значение. Именно так устроен гистерезис исходного алгоритма.

## Переменные и типы

| Тип | Пример | Назначение |
|---|---|---|
| BOOL | `TRUE`, `FALSE` | Кнопка, датчик, флаг |
| UINT | `0`, `3` | Неотрицательный счётчик; диапазон 0…65535 |
| INT | `-2`, `10` | Целое со знаком |
| REAL | `0.25` | Вещественное число |
| TIME | `T#30s`, `T#20ms` | Интервал времени |
| TON | `FillTimer` | Экземпляр таймера задержки включения |

В проекте переменные добавляют через таблицу редактора. Например: `StartCount`, тип `UINT`, Class `Local`, Initial `0`, Location пустой. Счётчик будет виден в отладке, но автоматически в HMI не появится.

В полном ST-файле объявление может выглядеть так:

```iecst
VAR
    StartCount : UINT := 0;
    PrevPump : BOOL := FALSE;
END_VAR
```

Эту секцию не вставляют в тело POU, если переменные уже объявлены в таблице.

## Выражения и условия

| Запись | Значение |
|---|---|
| `x := 3;` | Присваивание |
| `x = 3` | Проверка равенства |
| `x <> 3` | Не равно |
| `<`, `<=`, `>`, `>=` | Сравнение |
| `AND`, `OR`, `NOT` | Логические операции |
| `x + 1` | Арифметическое выражение |
| `(* комментарий *)` | Комментарий |

```iecst
IF StopBtn THEN
    AutoMode := FALSE;
ELSIF StartBtn AND NOT Alarm THEN
    AutoMode := TRUE;
END_IF;
```

Срабатывает только первая подходящая ветвь: здесь STOP приоритетнее START. В двух отдельных `IF` могут выполниться оба присваивания; последнее определит итоговое значение. Отступы помогают читать код, но не заменяют `END_IF;`.

Синтаксис и дополнительные конструкции: [справочник ST от ABB](https://help.plc.abb.com/cds_languages_st_u.html). Он относится к другой среде разработки: используйте описание языка, а не её интерфейса.

## TON: задержка включения

```iecst
FillTimer(IN := Pump, PT := T#30s);
IF FillTimer.Q THEN
    Alarm := TRUE;
    Pump := FALSE;
END_IF;
```

`IN` — условие отсчёта, `PT` — заданное время, `ET` — прошедшее время, `Q` — результат. При непрерывном `IN = TRUE` после достижения `PT` выход `Q` становится TRUE. Вызов с `IN = FALSE` сбрасывает отсчёт и Q. Вызывайте таймер каждый цикл, в том числе когда насос выключен. Это экземпляр блока с внутренним состоянием, а не команда «подождать 30 секунд». [Описание TON](https://en.help.plc.abb.com/TON.html).

## Как считать события, а не циклы

Код `IF Pump THEN StartCount := StartCount + 1; END_IF;` считает циклы PLC. За секунду работы насоса он прибавит примерно 50, хотя включение было одно.

Чтобы обнаружить переход FALSE → TRUE, сравните текущий сигнал с сохранённым предыдущим. Пример для произвольного сигнала:

```iecst
Rising := Signal AND NOT PreviousSignal;
(* Здесь обрабатывают Rising — он истинен один цикл. *)
PreviousSignal := Signal;
```

`Rising`, `Signal`, `PreviousSignal` имеют тип BOOL. Присваивание предыдущего состояния должно находиться после проверки фронта. Для задания используйте окончательное значение `Pump`, полученное после проверок аварий. Счётчик ограничьте заданным максимумом, чтобы избежать переполнения.

В библиотеке IEC также есть блок `R_TRIG`, но для работы достаточно явного сравнения.

## Адреса и видимость

`%MX0.3` — бит 3 байта 0 в области памяти M, `%QX1.0` — бит 0 байта 1 в области выходов Q. X обозначает битовую адресацию. Локальная переменная без Location хранится внутри экземпляра программы. Таблица Modbus — отдельное отображение этих областей; в нашем проекте MX начинается после 16 бит QX.

Отладка в редакторе показывает переменные PLC. Веб-HMI показывает только сигналы, явно прочитанные в `hmi/app.py`. Новые переменные задания наблюдайте в редакторе.
